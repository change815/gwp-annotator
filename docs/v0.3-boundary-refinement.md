# 胃癌白斑标注 V0.3 边界精修说明

## 1. 范围与兼容性

V0.3 在 V0.2.2 已有的自由圈选、动态 TOML 标签、代表图、视频截帧、立即保存和病例备份流程上增加“边界精修”。原有自由圈选仍用于创建区域；边界精修只修改当前选中的已保存区域，不重新填写或改变标签。

V0.3.1 调整自由圈选为“单击一次开始、松开后移动、回到起点自动闭合”，将轮廓改为中等深度蓝色，并强化已保存区域的启动回读：恢复成功时显示当前图片加载的区域数，右侧可手工“重新加载勾画”。完成病例备份、关闭应用并重新启动后，当前有效区域必须从 SQLite 回读；未闭合或未点 `OK` 的草稿仍不会保存。

本版继续使用单个、无孔洞的简单多边形。它不实现任意多区域画笔、孔洞、多组件几何、顶点拖拽、模型辅助或视频逐帧追踪。训练导出仍暂缓，但当前有效多边形、图片尺寸、代表图、标签和模板快照继续完整保存。

所有开发和验收只使用合成 fixture。不得读取、枚举、复制、散列、重命名或修改任何真实患者目录、图片或视频。原始数据根目录保持只读。

## 2. 医生交互

1. 在右侧选择一个已保存区域，点击“精修边界”。
2. 从 `4 / 8 / 16 / 24 px` 中选择笔刷粗细。这里的 px 是原始图片像素，不是屏幕 CSS 像素；改变缩放比例不会改变保存结果。
3. 一笔的模式在按下鼠标时确定并保持到松开：
   - 起点在当前区域内：擦除笔刷扫过的面积，边界向内收缩；
   - 起点在当前区域外且笔刷接触当前区域：加入笔刷扫过的面积，边界向外扩展。
4. 每笔松开后先更新内存草稿。可以“撤销一步”，也可以“取消”或按 `Esc` 丢弃全部未保存精修。
5. 点击“保存修正”并确认后，才将最终多边形写入 SQLite。保存失败时保留草稿，便于重试或取消。

精修期间不允许切换院区、病例、媒体、模板或代表图，也不允许进入平移、缩放、修改标签、删除或重画流程，避免未保存草稿被静默丢弃。自由圈选的原有标签弹窗、`OK`、`Cancel` 和 `Esc` 行为保持不变。

## 3. 受限几何规则

笔刷足迹是沿鼠标轨迹扫过的圆盘并集。前端在源图片像素网格上执行加减和轮廓重建，并在提交前执行拓扑检查。下列笔划必须整笔拒绝，原草稿保持不变：

- 外扩笔刷完全没有接触当前区域；
- 擦除后区域为空；
- 擦除后区域小于后端可可靠保存的最小归一化面积；
- 擦除后区域分裂为多个不相连部分；
- 擦除后产生孔洞；
- 结果无法形成一个有限、闭合、无自交的简单多边形；
- 输入尺寸、笔刷或结果复杂度超过安全上限。

实现不得通过只保留最大轮廓、自动填洞、凸包或删除小组件来“修复”结果，因为这些处理会静默改变医生的标注意义。医生可以撤销该笔，缩小笔刷或调整轨迹后重试；若确实需要删除整个区域，继续使用已有的“删除”操作。

## 4. 保存与审计

“保存修正”使用一次原生 IPC 和一个 SQLite `BEGIN IMMEDIATE` 事务完成。事务内验证区域仍为当前有效区域、仍属于当前病例/图片且提交基线未过期；然后只更新多边形和更新时间，保持 `region_id`、模板版本及标签不变。

每次成功保存写入一条 `geometry_refined` 操作记录，包含修改前后的完整多边形和相同的标签快照。冲突、无效多边形或事务失败不得留下部分更新或审计孤行。病例备份继续通过 SQLite Online Backup API 包含这些已提交状态。

## 5. 自动验收

从 `desktop/` 运行：

```bash
sh scripts/with-project-npm.sh run check:node
sh scripts/with-project-npm.sh run test
sh scripts/with-project-npm.sh run build
sh scripts/with-project-npm.sh run smoke
sh scripts/with-project-npm.sh run rust:fmt
sh scripts/with-project-npm.sh run rust:clippy
sh scripts/with-project-npm.sh run rust:test
sh scripts/with-project-npm.sh run rust:build
```

自动测试至少覆盖：内擦、贴边外扩、远离外扩拒绝、完全擦除拒绝、分裂拒绝、孔洞拒绝、不同笔刷尺寸、撤销/取消、保存冲突、SQLite 原子更新、审计快照、旧数据库迁移和未来 schema 拒绝。

## 6. Windows 合成复测

Windows 复测者只需要从最新 `main` 新建干净克隆，构建并安装 NSIS 包；不需要重复 macOS 已通过的 Rust 静态检查。若 Windows 编译本身报错，再保留首个完整错误进行诊断。

使用明确不含患者内容的合成图片完成以下检查：

1. 单击一次后松开左键，移动鼠标仍持续勾画并在回到起点时自动闭合；额外单击不重置草稿，`Esc` 取消，标签 `OK/Cancel/Esc` 行为不回退。
2. 选中已保存区域后可进入精修；未选区域时入口不可用。
3. `4 / 8 / 16 / 24 px` 笔刷圆形预览随图片缩放，但同一原图轨迹的保存结果不变。
4. 从区域内起笔边界内收，从区域外贴边起笔边界外扩；一笔跨越边界时模式不会中途翻转。
5. “撤销一步”、取消和 `Esc` 不写入 SQLite；切换病例、媒体和模板的入口在草稿期间不可用。
6. 尝试擦出孔洞、擦断窄连接、完全擦除和远处外扩，均看到清楚提示且原草稿不变。
7. 保存修正需要确认；成功后标签不变，重启仍显示修正后的蓝色轮廓；完成病例备份、关闭并重开后显示已加载区域数，也可点击“重新加载勾画”核对。
8. 结束时确认合成源目录的文件清单、大小、修改时间和散列与测试前一致，所有写入只发生在应用工作目录。

报告使用 `PASS`、`PARTIAL` 或 `BLOCKED`，附最新 main SHA、NSIS 路径、安装启动结果和上述人工步骤结果，并明确写明未访问真实患者媒体。
