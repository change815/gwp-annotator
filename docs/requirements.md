# 胃癌白斑标注 V0.1 需求说明

## 1. 文档状态与范围

本文只定义“胃癌术中白斑标注”Windows 单机软件的 V0.1。它服务于医生从院区病例目录中挑选代表图并圈选白斑区域，不定位为通用标注平台，也不作医疗诊断。

### 当前确认需求

| 主题 | 已确认需求 |
| --- | --- |
| 使用环境 | 医生在 Windows 上使用；软件应轻量，启动和浏览快，默认完全离线。 |
| 输入目录 | 数据根目录下有两个院区目录；每个院区有 100 多个病例文件夹。病例文件夹命名规则为“日期_病人名字”，通常含约 10 张 JPG 和 1--2 个 MP4。 |
| 原始数据保护 | 原始 JPG 和 MP4 只读使用，不改写、重命名、移动、删除或向原目录写入任何副文件。 |
| 主工作流 | 选择院区 -> 在侧栏选择病例文件夹 -> 在中央查看照片或视频 -> 用左右方向键浏览 -> 选择 1--2 张最清晰、适合训练的代表图 -> 标注。 |
| 代表图 | 每个病例最多选 2 张代表图；未标为代表图的媒体不得进入标注和训练导出。 |
| 圈选 | 默认工具为自动闭合自由圈选：左键单击起点后移动鼠标记录轨迹；回到起点附近自动闭合；随后显示标签小窗口。 |
| 标签窗口 | 小窗口根据外部标签模板生成下拉、单选、多选、必填项及选项，并提供 `OK` / `Cancel`。 |
| 保存 | 点击 `OK` 后立即保存本次区域和标签；`Cancel` 丢弃本次圈选。一个代表图可有多个区域。 |
| 视频 | V0.1 可播放浏览 MP4，并可截取当前帧。截帧作为派生图像进入同一代表图和圈选流程；不做视频逐帧追踪。 |
| 标签内容边界 | 当前仅确认“白斑形状”和“置信度”两个候选字段。不得内置或臆造其医学选项，其他字段由外部标签模板决定。 |
| 隐私 | 病例文件夹中的姓名可仅在本机界面显示；标注结果、训练导出、错误日志和本文档示例必须只使用脱敏病例 ID，绝不复制真实患者姓名。 |
| V0.1 排除项 | 不做模型预测、分期输入、强制双人标注、审核、登录、云服务或自动医疗诊断。 |

## 2. 用户流程和行为

1. 医生选择已配置的数据根目录中的一个院区。
2. 左侧显示该院区的病例列表；病例按日期降序排列，日期相同则使用稳定的脱敏病例 ID 排序。
3. 医生选择病例后，中部媒体查看器显示该病例的 JPG 与 MP4。左右方向键切换上一项和下一项媒体；焦点位于标签窗口或文本输入控件时，方向键不抢占其输入。
4. 医生将最清晰、适合训练的 1--2 张 JPG 或截取帧标记为代表图。尝试选择第 3 张时，界面保留现有选择并提示先取消一张。
5. 医生打开一张代表图，使用默认自由圈选工具完成一个区域。闭合后按外部模板填写标签：模板规定的必填项未完成时，`OK` 不可用。
6. 点击 `OK` 后，区域和标签立即持久化；继续重复可为同一代表图增加多个区域。点击 `Cancel` 或按 `Esc` 时，本次尚未保存的轨迹和标签全部丢弃。
7. 医生可在本机生成训练导出。导出只包含已选代表图及其已保存区域，并使用脱敏 ID 命名。

## 3. 输入、显示与隐私约束

### 3.1 目录约定

输入根目录的第一层是两个院区目录，第二层是病例目录。下例中的尖括号和 `CASE` 都是占位符，不是患者姓名：

```text
<数据根目录>/
  院区_A/
    <日期>_<患者姓名占位符>/
      IMG_0001.JPG
      IMG_0002.JPG
      VIDEO_0001.MP4
  院区_B/
    <日期>_<患者姓名占位符>/
      IMG_0001.JPG
      VIDEO_0001.MP4
```

扫描只识别病例目录第一层中的 `.jpg`、`.jpeg`、`.mp4`（大小写不敏感）；不递归扫描其他子目录。扫描阶段只读取目录项和文件元数据，只有医生打开某一媒体时才按需解码该媒体。

### 3.2 脱敏标识

- 软件为每个病例生成稳定、不含姓名的 `CASE-...` ID；结果、导出、缓存文件名和日志只使用该 ID。
- 原始病例目录名只可用于当前本机进程中的侧栏显示和打开对应文件，不能写入标注数据库、标注 JSON、训练导出、截图导出或诊断日志。
- 原始媒体的路径、文件夹名和 EXIF 中可能存在的姓名不得写入导出。训练图像导出时必须使用脱敏文件名并移除 EXIF。

## 4. 标签模板需求

正式标签模板采用版本化 JSON，支持以下字段属性：

- `id`：稳定的机器字段 ID。
- `label`：本机界面显示名。
- `control`：`dropdown`、`single_select` 或 `multi_select`。
- `required`：布尔值，决定是否允许 `OK`。
- `options`：带稳定 `id` 和显示 `label` 的选项列表。

为便于医生快速导入，允许简化的 `label.txt`：每行 `[*]字段名=选项A|选项B|...`。星号表示必填；该简化格式一律导入为下拉控件。需要单选或多选时，应使用正式 JSON 模板。

模板加载时必须校验字段 ID、选项 ID 的唯一性及必填字段是否有可选项。保存标注时记录模板版本和选项 ID，避免模板显示文字改动后丢失历史语义。

## 5. 非功能需求

- 默认不联网；无登录、云同步、遥测或在线模型下载。
- 数据根目录必须以只读方式打开；派生截帧、缩略图、数据库、恢复文件和导出均放在应用自己的项目工作目录。
- 首次扫描应对约 2 个院区、各 100 多病例、每例约 10 个 JPG 和 1--2 个 MP4 保持可用；缩略图和媒体解码均按需加载，不能阻塞病例列表。
- 已点击 `OK` 的标注在进程异常退出后必须可恢复；未确认的圈选不得被误标为已保存。
- 所有保存和导出失败都应显示可操作错误信息，且不能静默丢失已确认标注。

## 6. 后续可选功能（非 V0.1）

- 模板编辑器、模板签名和模板版本迁移助手。
- 区域编辑、撤销/重做、快捷键自定义和病例筛选。
- 更丰富的图像格式、更多视频编码兼容性和批量导入报告。
- 双人标注、审核流、登录、同步、模型辅助建议和研究数据管理。

这些功能均不是 V0.1 的交付条件，不能以占位实现冒充已交付能力。

## 7. 唯一待确认问题

请由医学负责人提供首版标签模板中“白斑形状”和“置信度”的**具体选项列表及各字段是否必填**。在此之前，V0.1 只提供模板机制和不带医学词表的示例占位项，不能自行补全医学选项。
