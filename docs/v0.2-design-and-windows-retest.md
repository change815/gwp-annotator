# 胃癌白斑标注 V0.2.1 设计说明与 Windows 复测

## 1. 范围和优先级

本文件定义 V0.2.1，且覆盖 V0.1/V0.2 文档中与之冲突的内容：正式模板格式为 TOML，当前模板可以受控更换；训练导出仍暂缓。软件仍是 Windows 单机、默认离线的胃外表白斑区域标注工具，不是通用标注平台或医疗诊断系统。

V0.2.1 继续保留已通过的图片工作流：选择根目录、浏览院区和病例、代表图不限数量、自由手绘自动闭合、标签弹窗 `OK` / `Cancel` / `Esc`，以及每次 `OK` 的立即保存。原始数据根目录始终只读。

## 2. 隐私与本地工作目录

病例目录的显示文字只用于当前本机界面浏览，不进入 SQLite、备份、截帧、训练导出、日志、测试夹具或 Git。原始图片、视频、文件名和病例子目录名都不复制、不改名、不写回、不删除。

Windows 工作目录跟随安装位置所在磁盘，但不放进安装器可能覆盖或删除的程序目录内部。若程序位于 `D:\Apps\GWP Annotator\`，工作目录默认为同级的 `D:\Apps\GWP Annotator Data\PROJECT-LOCAL\`；界面可直接显示实际路径。这样安装在 D 盘时，SQLite、截帧和备份也写入 D 盘。旧版 `%LOCALAPPDATA%` 测试数据不会未经确认自动复制或删除。

应用工作目录的结构如下；所有 ID 都是不含显示名的 `CASE-...`、`ASSET-...` 等不透明 ID。

```text
PROJECT-LOCAL/
  annotations.sqlite3
  templates/
    active-template.manifest.json
    immutable/
      <template-content-sha256>.toml
  session/
    project-session.json
  captures/
    CASE-.../
      FRAME-ASSET-....png
  backups/
    CASE-.../
      backup-<time>-<sequence>/
        annotations.sqlite3
        label-template-v1.toml
        captures/
        manifest.json
```

唯一例外是 `session/project-session.json`：它为下次启动保存用户选择的**最外层数据根目录路径**、当前 `CASE-...` / `ASSET-...` 和当前模板校验值。它不保存病例子目录显示名、原始媒体路径或原始文件名；也绝不复制进 SQLite、备份、训练导出、日志或 Git。点击“忘记上次位置”会移除该会话文件，模板归档和已保存标注不受影响。

首次选择根目录后，下一次启动会重新扫描该根目录、加载当前模板，并尝试恢复上次 `CASE-...` 和 `ASSET-...`。根目录不可用、上次媒体不存在、模板缺失或校验不匹配时，界面必须说明原因并要求重新选择或恢复模板，不能静默失败。

## 3. 可更换的 TOML 标签模板

医生首次导入 `label-template-v1.toml` 后，应用保存校验过的项目副本并在后续启动自动加载。模板栏始终保留“更换模板”入口；更换前必须确认，成功后新圈选和“删除后重画”使用新模板。已有区域不做任何按显示名或选项顺序的自动转换，而是继续引用 SQLite 中保存的原模板快照，并可按原模板修改标签。

若某个 `(template_id, version)` 已经用于保存区域，则同一 ID 和版本的内容不可改写；负责人应增加 `version` 或更换 `template_id`。尚未产生标注的试用模板可以在确认后修订。应用保留历史模板快照，当前模板的切换不得覆盖旧区域的解释依据。

正式模板字段和选项的 ID 必须稳定、唯一，并由医学负责人定义具体显示名与选项。应用不内置或推测医学词表。以下是结构示例，字段和选项均为中性占位符：

```toml
format = "gwa-label-template"
version = 1
template_id = "template-v1"

[[fields]]
id = "field_alpha"
label = "字段 A"
control = "dropdown"
required = true

[[fields.options]]
id = "alpha_1"
label = "选项 A1"

[[fields.options]]
id = "alpha_2"
label = "选项 A2"

[[fields]]
id = "field_beta"
label = "字段 B"
control = "single_select"
required = true

[[fields.options]]
id = "beta_1"
label = "选项 B1"

[[fields.options]]
id = "beta_2"
label = "选项 B2"

[[fields]]
id = "field_gamma"
label = "字段 C"
control = "multi_select"
required = true

[[fields.options]]
id = "gamma_1"
label = "选项 C1"

[[fields.options]]
id = "gamma_2"
label = "选项 C2"
```

`control` 只能是 `dropdown`、`single_select` 或 `multi_select`。下拉和单选必须保存一个 option ID；多选必须保存一个非空、无重复 option ID 数组。必填字段没有有效值时，标签弹窗 `OK` 不可用。格式错误、空 ID、重复 ID、未知控件、空显示名，以及没有选项的必填字段都必须拒绝。

旧 `label.txt` 可仅用于首次兼容导入，导入后立即转换为项目内 TOML；其所有字段均按下拉控件处理，无法表达正式的单选或多选语义。更换模板只接受 TOML。JSON 仅可作为内部表示或兼容能力，不是医生的日常维护格式。

## 4. 已保存区域的修正

已保存区域可在区域列表中选中，并在明确确认后执行以下操作：

| 操作 | 行为 |
| --- | --- |
| 修改标签 | 保持几何不变，使用该区域保存时的历史模板重新填写并确认标签。 |
| 删除 | 将区域标记为删除，不静默抹除其历史。 |
| 删除后重画 | 医生重新圈选、填写标签并确认；旧区域和新区域建立替换关系。 |

创建、修改标签、删除和替换都记录操作时间、原/新多边形及原/新标签快照。训练导出以后只读取当前有效区域。V0.2 **不实现顶点拖拽编辑**；采用“删除后重画”以减少误操作风险。`Cancel` 或 `Esc` 始终只丢弃当前未确认草稿，绝不修改已有区域。

## 5. 立即保存与病例备份

每次标签窗口点击 `OK` 后，区域、多边形、标签和必要操作记录在一个 SQLite 事务内提交；仅在提交成功后界面才显示已保存。崩溃时最多丢失尚未点击 `OK` 的草稿。

“完成本病例并备份”是显式操作。它使用 SQLite Online Backup API 生成一致的数据库快照，而不是直接复制可能处于 WAL 状态的主数据库；随后加入当前模板归档和该病例的已持久化截帧，最后写入 `manifest.json`。没有完成清单的中断目录不视为可恢复备份。备份失败必须提示，但不得回滚已提交标注或改动源目录。

## 6. MP4 播放与截帧

MP4 在本地 WebView 中离线播放，至少提供播放/暂停、进度拖动和当前时间显示。对当前 Windows 解码器不支持的本地编码，界面显示清晰错误；不得联网下载编解码器、转码或修改源视频。

点击“截取当前帧”后，当前画面作为 PNG 写入 `captures/CASE-.../FRAME-ASSET-....png`，并立即加入同一病例的媒体列表。截帧可以不限数量地设为代表图、圈选、按当前模板标注，并在下次启动后仍可回读。每个截帧保存其父视频 `ASSET-...`、截取时间、宽高和字节数，便于之后追溯。截帧只在界面中归属于原病例，绝不物理写入原病例目录。

## 7. 为后续训练保留的数据与非目标

SQLite 仍是唯一主存档。有效区域保留归一化多边形、图像尺寸、代表图状态、标签 option ID、模板定义、区域修正关系，以及截帧来源；这些信息足以在后续无需重新圈选地转换为 YOLO Segmentation、COCO 或完整归档 JSON。当前不提供训练导出界面。

V0.2.1 明确不包括：

- 批量脱敏、病例编号、真实对应表、重命名或复制患者媒体；
- 模型训练、分期预测、自动诊断、阴性图片状态；
- 云服务、网络同步、账号、双人审核或视频逐帧追踪；
- 模板编辑器、旧标签自动迁移或顶点拖拽编辑。

## 8. Windows 手工复测清单

复测者只使用新建的合成 fixture 和最新 `main`，不得打开、枚举、复制、散列、重命名或修改任何真实患者目录、图片或视频。

1. 在新的非临床克隆目录执行 `git status --short`，确认没有输出；随后执行 `git fetch origin main`、`git switch main`、`git pull --ff-only origin main`、`git rev-parse HEAD`，记录 SHA。若工作树不干净或更新不是快进，停止处理该目录并换用新克隆，不执行 `reset` 或 `clean`。
2. 开发侧先完成前端测试、构建、smoke、Rust fmt/clippy/test/build。Windows 人工复测不重复这些检查，直接进入 `desktop` 执行 `npx --no-install tauri build --bundles nsis`，安装刚构建的 NSIS 包并启动应用。打包本身会编译 Windows Rust/Tauri 代码；只有出现真实编译错误时才补充平台诊断。
3. 新建合成根目录：至少两个院区、各至少一个仅含 `CASE-...` 占位目录的病例；测试病例包含多张合成 JPG 与一段可在该 Windows 设备播放的合成 MP4。记录该合成源目录中文件名、大小、修改时间和散列，供结束时比较。不要把 fixture 或产物提交到 Git。
4. 首次选择该合成根目录，导入本文件第 3 节的 TOML。确认下拉、单选、多选及必填限制均正确；再导入增加了 `version` 的合成 TOML，确认新圈选使用新模板、旧区域仍按旧模板显示和修改。重启应用，确认根目录、当前模板、上次病例和图片自动恢复。
5. 选择任意数量的代表图片，完成并保存区域。对已保存区域分别验证“修改标签”“删除后重画”和“删除”均需要确认；重启后确认当前有效区域回读，取消或按 `Esc` 的草稿没有保存。
6. 点击“完成本病例并备份”，确认成功提示和可恢复备份；保留应用工作目录中的备份证据，但不把它加入 Git。
7. 播放合成 MP4、暂停、拖动进度并确认时间显示；在不同时间点截取至少两帧。确认帧出现在同一病例下、可设为代表图并标注；重启后仍存在。比较第 3 步记录，确认合成源目录及原 MP4 完全未变化。
8. 点击“数据保存位置”，确认安装在 D 盘时显示的工作目录也位于 D 盘，并位于安装目录旁的 `GWP Annotator Data`，而不是源病例目录或默认 C 盘应用数据目录。

报告应标为 `PASS`、`PARTIAL` 或 `BLOCKED`，附实际 main SHA、命令退出码、安装启动结果、合成 fixture 描述、通过/失败项及原始错误。报告必须明确写明：未访问真实患者媒体。
