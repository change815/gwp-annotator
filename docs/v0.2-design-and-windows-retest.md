# 胃癌白斑标注 V0.2.2 设计说明与 Windows 复测

## 1. 范围和优先级

本文件定义 V0.2.2，且覆盖 V0.1/V0.2/V0.2.1 文档中与之冲突的内容：正式模板格式为 TOML，当前模板可以受控更换；训练导出仍暂缓。软件仍是 Windows 单机、默认离线的胃外表白斑区域标注工具，不是通用标注平台或医疗诊断系统。

V0.2.2 继续保留已通过的图片工作流：选择根目录、浏览一个或多个任意命名（可含中文）的院区和病例、代表图不限数量、自由手绘自动闭合、标签弹窗 `OK` / `Cancel` / `Esc`，以及每次 `OK` 的立即保存。原始数据根目录始终只读。

## 2. 隐私与本地工作目录

院区和病例目录的显示文字只用于当前本机界面浏览；院区数为 1 个或更多时均有效，UI 原样显示本机真实目录名。显示文字不进入 SQLite、备份、截帧、训练导出、日志、测试夹具或 Git。原始图片、视频、文件名和病例子目录名都不复制、不改名、不写回、不删除。

Windows 工作目录跟随安装位置所在磁盘，但不放进安装器可能覆盖或删除的程序目录内部。若程序位于 `D:\Apps\GWP Annotator\`，工作目录默认为同级的 `D:\Apps\GWP Annotator Data\PROJECT-LOCAL\`；界面可直接显示实际路径。这样安装在 D 盘时，SQLite、截帧和备份也写入 D 盘。旧版 `%LOCALAPPDATA%` 测试数据不会未经确认自动复制或删除。

应用工作目录的结构如下；所有 ID 都是不含显示名的 `CASE-...`、`ASSET-...` 等不透明 ID。

```text
PROJECT-LOCAL/
  annotations.sqlite3
  templates/
    active-template.manifest.json
    immutable/
      <template-content-sha256>.toml
  session/
    project-session.json
  captures/
    CASE-.../
      FRAME-ASSET-....png
  backups/
    current/
      annotations.sqlite3
      label-template-v1.toml
      captures/
        CASE-.../
          FRAME-ASSET-....png
      manifest.json
```

唯一例外是 `session/project-session.json`：它为下次启动保存用户选择的**最外层数据根目录路径**、当前 `CASE-...` / `ASSET-...` 和当前模板校验值。它不保存院区/病例子目录显示名、原始媒体路径或原始文件名；也绝不复制进 SQLite、备份、训练导出、日志或 Git。点击“忘记上次位置”会移除该会话文件，模板归档和已保存标注不受影响。

首次选择根目录后，下一次启动会重新扫描该根目录、加载当前模板，并尝试恢复上次 `CASE-...` 和 `ASSET-...`。根目录不可用、上次媒体不存在、模板缺失或校验不匹配时，界面必须说明原因并要求重新选择或恢复模板，不能静默失败。

## 3. 可更换的 TOML 标签模板

医生首次导入 `label-template-v1.toml` 后，应用保存校验过的项目副本并在后续启动自动加载。模板栏始终保留“更换模板”入口；更换前必须确认，成功后新圈选和“删除后重画”使用新模板。已有区域不做任何按显示名或选项顺序的自动转换，而是继续引用 SQLite 中保存的原模板快照，并可按原模板修改标签。

正式模板是严格 UTF-8 TOML。导入器必须先以 UTF-8 解码字节；解码错误、Unicode 替换字符 `U+FFFD` 或明显乱码均必须拒绝，提示用户另存为 UTF-8 后再试。不得猜测或转换 GBK、系统代码页或其他编码；首次导入和更换模板都遵循此规则。

升级前已经保存且校验和一致的旧乱码模板和历史区域仍可读取，避免锁死已有项目；界面必须提示更换模板，并禁止该模板继续用于新圈选或“删除后重画”。历史区域仍可查看、修改标签或删除，替换为干净 UTF-8 TOML 后才恢复新区域标注。

若某个 `(template_id, version)` 已经用于保存区域，则同一 ID 和版本的内容不可改写；负责人应增加 `version` 或更换 `template_id`。尚未产生标注的试用模板可以在确认后修订。应用保留历史模板快照，当前模板的切换不得覆盖旧区域的解释依据。

正式研究使用已提交的医生确认模板 [`desktop/templates/label-template-v1.toml`](../desktop/templates/label-template-v1.toml)，其字段和选项 ID 稳定、唯一。三个字段均为必填的 `single_select`，前端应平铺渲染为单选按钮组，不能渲染为下拉菜单：

| 字段 | 控件 | 选项 |
| --- | --- | --- |
| 浆膜分型 | `single_select`，必填 | 正常型、反应型、突出结节型、扁平结节型、腱状型、多彩弥漫型 |
| 浆膜白斑分型 | `single_select`，必填 | 突出型、扁平型、凹陷型 |
| 浆膜白斑置信度 | `single_select`，必填 | 50%、80%、100% |

`control` 只能是 `dropdown`、`single_select` 或 `multi_select`。下拉和单选必须保存一个 option ID；多选必须保存一个非空、无重复 option ID 数组。必填字段没有有效值时，标签弹窗 `OK` 不可用。格式错误、空 ID、重复 ID、未知控件、空显示名，以及没有选项的必填字段都必须拒绝。医生的当前正式研究模板仅使用上述平铺单选控件；引擎保留 `dropdown` 与 `multi_select` 解析能力，以兼容历史或 `label.txt` 转换模板。Windows PowerShell 创建合成模板时，优先以仅 ASCII 的 TOML `\uXXXX` 转义表示中文；需要写入实际中文字符时，必须显式写出 UTF-8 无 BOM 文件，不能依赖 PowerShell 的默认编码。

旧 `label.txt` 可仅用于首次兼容导入，导入后立即转换为项目内 TOML；其所有字段均按下拉控件处理，无法表达正式的单选或多选语义。更换模板只接受 TOML。JSON 仅可作为内部表示或兼容能力，不是医生的日常维护格式。

## 4. 已保存区域的修正

已保存区域可在区域列表中选中，并在明确确认后执行以下操作：

| 操作 | 行为 |
| --- | --- |
| 修改标签 | 保持几何不变，使用该区域保存时的历史模板重新填写并确认标签。 |
| 删除 | 将区域标记为删除，不静默抹除其历史。 |
| 删除后重画 | 医生重新圈选、填写标签并确认；旧区域和新区域建立替换关系。 |

创建、修改标签、删除和替换都记录操作时间、原/新多边形及原/新标签快照。训练导出以后只读取当前有效区域。V0.2 **不实现顶点拖拽编辑**；采用“删除后重画”以减少误操作风险。`Cancel` 或 `Esc` 始终只丢弃当前未确认草稿，绝不修改已有区域。

## 5. 立即保存与病例备份

每次标签窗口点击 `OK` 后，区域、多边形、标签和必要操作记录在一个 SQLite 事务内提交；仅在提交成功后界面才显示已保存。崩溃时最多丢失尚未点击 `OK` 的草稿。

“完成本病例并备份”是显式操作。它使用 SQLite Online Backup API 生成一致的全项目数据库快照，而不是直接复制可能处于 WAL 状态的主数据库；随后加入当前模板和数据库引用的全部已持久化截帧，最后写入 `manifest.json`。完整快照通过暂存目录原子发布到固定的 `backups/current/`，后一次成功备份覆盖前一次，不再按病例或时间戳持续新增版本。发布失败时保留上一份完整快照，并且不得回滚已经提交的主库标注或改动源目录。

`annotations.sqlite3` 始终是即时保存和正常启动时读取的唯一主存档；“重新加载项目数据”和启动恢复都读取主库，不能拿可能较旧的备份覆盖刚点击 `OK` 保存的区域。`backups/current/` 只用于主库损坏后的恢复。旧版生成的 `backups/CASE-.../backup-.../` 不再参与加载，也不会继续增长；在新快照完成 Windows 验收前不自动删除这些旧恢复副本。

## 6. MP4 播放与截帧

MP4 在本地 WebView 中离线播放，至少提供播放/暂停、进度拖动和当前时间显示。对当前 Windows 解码器不支持的本地编码，界面显示清晰错误；不得联网下载编解码器、转码或修改源视频。

点击“截取当前帧”后，当前画面作为 PNG 写入 `captures/CASE-.../FRAME-ASSET-....png`，并立即加入同一病例的媒体列表。截帧可以不限数量地设为代表图、圈选、按当前模板标注，并在下次启动后仍可回读。每个截帧保存其父视频 `ASSET-...`、截取时间、宽高和字节数，便于之后追溯。截帧只在界面中归属于原病例，绝不物理写入原病例目录。

## 7. 为后续训练保留的数据与非目标

SQLite 仍是唯一主存档。有效区域保留归一化多边形、图像尺寸、代表图状态、标签 option ID、模板定义、区域修正关系，以及截帧来源；这些信息足以在后续无需重新圈选地转换为 YOLO Segmentation、COCO 或完整归档 JSON。当前不提供训练导出界面。

V0.2.2 明确不包括：

- 批量脱敏、病例编号、真实对应表、重命名或复制患者媒体；
- 模型训练、分期预测、自动诊断、阴性图片状态；
- 云服务、网络同步、账号、双人审核或视频逐帧追踪；
- 模板编辑器、旧标签自动迁移或顶点拖拽编辑。

## 8. Windows 手工复测清单

复测者只使用新建的合成 fixture 和最新 `main`，不得打开、枚举、复制、散列、重命名或修改任何真实患者目录、图片或视频。

### 8.1 PowerShell 合成模板写入

Windows PowerShell 不能用默认编码生成模板。优先生成只含 ASCII 的 TOML，并用 `\uXXXX` 转义产生中文显示名；下例显式以 UTF-8 无 BOM 写入，因此也可作为“合法中文模板”测试的基础。所有名称均为合成名称。

```powershell
$utf8NoBom = [System.Text.UTF8Encoding]::new($false)
$templatePath = Join-Path $env:TEMP 'label-template-ascii.toml'
$asciiToml = @'
format = "gwa-label-template"
version = 1
template_id = "template-synthetic"

[[fields]]
id = "field_alpha"
label = "\u5B57\u6BB5 A"
control = "dropdown"
required = true

[[fields.options]]
id = "option_alpha"
label = "\u9009\u9879 A"

[[fields]]
id = "field_beta"
label = "\u5B57\u6BB5 B"
control = "single_select"
required = true

[[fields.options]]
id = "option_beta"
label = "\u9009\u9879 B"

[[fields]]
id = "field_gamma"
label = "\u5B57\u6BB5 C"
control = "multi_select"
required = true

[[fields.options]]
id = "option_gamma"
label = "\u9009\u9879 C"
'@
[System.IO.File]::WriteAllText($templatePath, $asciiToml, $utf8NoBom)

# Build actual Chinese characters from code points, then write explicit UTF-8 without a BOM.
# The PowerShell source remains ASCII, so copying this block does not depend on a console code page.
$validChinesePath = Join-Path $env:TEMP 'label-template-utf8-chinese.toml'
$fieldWord = [string]([char]0x5B57) + [char]0x6BB5
$optionWord = [string]([char]0x9009) + [char]0x9879
$validChineseToml = $asciiToml.Replace('\u5B57\u6BB5', $fieldWord).Replace('\u9009\u9879', $optionWord)
[System.IO.File]::WriteAllText($validChinesePath, $validChineseToml, $utf8NoBom)

# Deliberately invalid UTF-8: prepend an invalid byte to the otherwise valid template.
$invalidUtf8Path = Join-Path $env:TEMP 'label-template-invalid-utf8.toml'
$invalidBytes = [byte[]](@(0x80) + [System.IO.File]::ReadAllBytes($templatePath))
[System.IO.File]::WriteAllBytes($invalidUtf8Path, $invalidBytes)

# Deliberately include U+FFFD in a valid UTF-8 file; it must also be rejected.
$replacementPath = Join-Path $env:TEMP 'label-template-replacement.toml'
$replacementToml = $validChineseToml.Replace(($fieldWord + ' A'), ($fieldWord + ' ' + [char]0xFFFD))
[System.IO.File]::WriteAllText($replacementPath, $replacementToml, $utf8NoBom)

# Deliberately obvious mojibake in a valid UTF-8 file; it must also be rejected.
$mojibakePath = Join-Path $env:TEMP 'label-template-mojibake.toml'
$mojibakeLabel = [string]([char]0x95AB) + [char]0x5910 + [char]0x300D
$mojibakeToml = $validChineseToml.Replace(($fieldWord + ' A'), $mojibakeLabel)
[System.IO.File]::WriteAllText($mojibakePath, $mojibakeToml, $utf8NoBom)
```

1. 在新的非临床克隆目录执行 `git status --short`，确认没有输出；随后执行 `git fetch origin main`、`git switch main`、`git pull --ff-only origin main`、`git rev-parse HEAD`，记录 SHA。若工作树不干净或更新不是快进，停止处理该目录并换用新克隆，不执行 `reset` 或 `clean`。
2. 开发侧先完成前端测试、构建、smoke、Rust fmt/clippy/test/build。Windows 人工复测不重复这些检查，直接进入 `desktop` 执行 `npx --no-install tauri build --bundles nsis`，安装刚构建的 NSIS 包并启动应用。打包本身会编译 Windows Rust/Tauri 代码；只有出现真实编译错误时才补充平台诊断。
3. 新建两个合成根目录。第一个只含一个 `CAMPUS-ONE/CASE-001/` 院区/病例布局；第二个含三个或更多任意命名院区，其中至少一个为中文合成名（例如 `CAMPUS-ONE/`、`院区-乙/`、`CAMPUS-THREE/`），每个院区至少一个 `CASE-...` 病例。测试病例包含多张合成 JPG 与一段可在该 Windows 设备播放的合成 MP4；媒体仅用 `ASSET-...` 占位名。记录合成源目录中文件名、大小、修改时间和散列，供结束时比较。不要把 fixture 或产物提交到 Git。
4. 依次选择单院区根目录和多院区根目录。确认 1 个与 3 个以上院区都不会触发数量错误，且 UI 原样显示 `院区-乙` 等本机目录名。空根目录或没有可用院区目录必须报错。
5. 导入仓库中的 `desktop/templates/label-template-v1.toml`，确认三个正式字段逐字正确，合计显示 12 个平铺单选项、0 个标签下拉框、0 个复选框，且未完成任一必填字段时不能确认。打开已保存区域的“修改标签”，依次更换三个值，确认弹窗不会关闭或闪退；提交并再次打开后应回读新值。重启应用，确认根目录、当前模板、上次病例和图片自动恢复。上述 ASCII/非法编码模板仅作为兼容与错误处理的可选扩展检查。
6. 选择任意数量的代表图片，完成并保存区域。对已保存区域分别验证“修改标签”“删除后重画”和“删除”均需要确认；开始一笔新圈选后单击鼠标右键，确认只取消当前未保存草稿且已保存区域不变。`Esc` 和 `Cancel` 应有相同的数据丢弃边界；重启后确认当前有效区域回读。
7. 连续两次点击“完成本病例并备份”，确认始终只有一个 `backups/current/` 完整快照，第二次包含最新已提交区域和全部病例截帧；检查 SQLite、备份、日志和导出均不含 `CAMPUS-ONE`、`院区-乙` 等合成源院区目录名。保留应用工作目录中的备份证据，但不把 fixture、备份或其他运行产物加入 Git。
8. 播放合成 MP4、暂停、拖动进度并确认时间显示；在不同时间点截取至少两帧。确认帧出现在同一病例下、可设为代表图并标注；重启后仍存在。比较第 3 步记录，确认合成源目录及原 MP4 完全未变化。
9. 点击“数据保存位置”，确认安装在 D 盘时显示的工作目录也位于 D 盘，并位于安装目录旁的 `GWP Annotator Data`，而不是源病例目录或默认 C 盘应用数据目录。
